# Audit, 19 Nov — what was falsified and what it found

Every claim below was tested by breaking something and checking that the system noticed. **A safety net
that never fires is not a safety net**, and the only way to know is to make it fire.

## Falsified, and correctly caught

| mechanism | how it was broken | result |
|---|---|---|
| `regress.py` — .docx table | a document's share5 set to 99.0, committed, engine untouched | **REFUSED**, exit 1 |
| `regress.py` — .txt table | a document's `failed_ids` set from `-` to `t13`, committed | **REFUSED**, exit 1 |
| `regress.py` — honest state | nothing | PASS, exit 0 |
| `health.py --stalled` | `fixer_started` set 5 hours in the past | `STOPPED: fix`, exit 1 |
| `round.py --reopen` | phase forced to `done`, round 3 of 3 | `reopened as round 4`, phase `measure` |
| `round.py --claim-fixer` while done | phase forced to `done` | refused, exit 1 |
| `round.py --reopen` when not done | phase `fix` | `refused: the phase is fix, not done` |
| `stage.py --set` past the evidence | asked for `fix` while measuring | `refused: the evidence says measure-google` |

## The hole this audit found

`regress.py` skipped its table check whenever the engine had not changed:

    d_bad, d_err = docx_regressions() if need_docx else ([], "")
    t_bad, t_err = txt_regressions() if need_txt else ([], "")

**A document went from 0.00 to 99.00 and the gate answered PASS**, with
`docx: not re-measured - the tree is the engine the table was measured on`.

The stamp says the table was *made by* this engine. It does not say the numbers in it are right. A
baseline run re-measures every document and can write a worse table without touching a line of engine
code — a soffice failure, a truncated render, a bad read. Over two months that is the difference between
a ratchet and a table nobody is checking.

Both formats now check every time. Reading two CSVs costs milliseconds.

## Checked and clean

* **Numbers agree everywhere**: corpus 213, docx open 65, txt failing 47, Google 90 of which 84 scored,
  6 refused, 7 clean. The same figures in `RANKING.csv`, `RANKING-TXT.csv`, `benchmarks/gverify/`,
  `PROGRESS.md` and `SYSTEM.md`.
* **Every command in every brief runs.** No missing script, no unparseable file, no flag a tool does not
  accept.
* **Every state file the briefs name exists** — 14 of 14.
* **Corpus intact**: 213 PDFs, 213 .docx, none missing, none suspiciously small.
* **All six crons enabled** with a future fire time; the fixer was recreated and has no zombie.
* **`archive.py` is wired in** and idempotent (`already done today`), so the logs rotate rather than
  grow: TIMELINE 44 K, TRACE 25 K, ATTEMPTS 30 K after two days. Nothing unbounded.

## Two mistakes of mine, recorded so they are not repeated

1. **A falsification that could not fail.** I first broke the .txt by changing the `failed` count
   column; `read_txt` reads `failed_ids`, so nothing changed and I briefly believed the gate had a hole
   it did not have. A test that cannot fail is not a test.
2. **`git reset --hard` over uncommitted work.** I used it to undo a falsification commit and it wiped
   the fix I had just written — twice. Every brief in this repository warns about it, and the warning
   was right. Patch, commit, then falsify.

## What is still not proven

the truth; none of it is about whether the converter is right.**
